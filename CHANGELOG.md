# Changelog

All notable changes to Quotalis (called Claudex before 0.7.0) are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Added

- **Your GitHub contributions in the Git tab.** A heatmap of soybean-alien's GitHub contribution calendar, the last 26 weeks, laid out like the usage heatmap but in GitHub's own dark-mode greens and its five levels, with the total and active days. Hover a day for "Oct 24: 3 contributions", click to keep it. Read through the signed-in GitHub CLI (`gh api graphql`, read-only) when Git opens, at most every 15 minutes; another signed-in account, no CLI or no sign-in shows a short note instead.

### Changed

- **Claudex is now Quotalis.** New name everywhere: the app, `Quotalis.exe`, the installer (`Quotalis-Setup-X.Y.Z.exe`), Start menu, tray, Settings, the code (`Quotalis`, `Quotalis.Core`, `Quotalis.Tests`) and the repository (`soybean-alien/Quotalis`). Updating from Claudex keeps everything:
  - **Settings, history and sign-ins move over** on the first start: `%LOCALAPPDATA%\Claudex` becomes `%LOCALAPPDATA%\Quotalis`, `%USERPROFILE%\.claudex` becomes `%USERPROFILE%\.quotalis` (claude.ai, ChatGPT and Nous sign-ins included). Files a hook already wrote under the new name are kept, and their older Claudex copies stay in the old folder instead of being deleted. Only the installed copy moves anything: a development build or demo run leaves Claudex's folders alone, and a `Quotalis` folder it made earlier is set aside (renamed `….before-claudex-<time>`, not deleted) when the installed copy moves the real one in.
  - **The installer upgrades Claudex in place** (same installer id): it installs to `Programs\Quotalis`, removes `Programs\Claudex` and its shortcuts and Run entry, and points the Claude Code status line and the Codex Stop hook at `Quotalis.exe`, also when the hook task isn't chosen (`--quotalis-hooks repoint` changes only entries that already exist, and renames the Codex hook's "Claudex usage check" label).
  - **Command-line arguments are `--quotalis-…`** (`--quotalis-statusline`, `--quotalis-codex-stop-hook`, `--quotalis-calibrate`, `--quotalis-hooks`, `--quotalis-import-codex-profile`); the `--claudex-…` names still work.
  - **"Start with Windows"** replaces Claudex's Run entry with Quotalis's.
  - **Releases carry the installer twice,** also as `Claudex-Setup-X.Y.Z.exe` (listed in `SHA256SUMS`), so a Claudex that hasn't updated yet still finds it.
  - The Claudex Mini Stream Deck plugin still reads `%USERPROFILE%\.claudex`; it needs its own update to read `.quotalis`.
- **The updater no longer needs the GitHub CLI.** It reads the latest release from GitHub's public API and downloads the installer from the release's own link, without an account, then checks its SHA-256 as before. Only while the repository is private (GitHub answers "not found" to anonymous requests) does it fall back to the signed-in GitHub CLI, as before. A used-up anonymous request limit gets its own message.

### Removed

- **Quotalis is now about AI usage limits and Git (version 0.7.0).** Music, Focus, Tasks, Calendar, System (hardware sensors), Awake, Home Cloud and the GitHub module are gone, with their Settings, tray items and code. What stays: Claude, Codex and Hermes in the Usage tab, the Git tab, the camera and microphone marks, auto-hide, the usage strip and the updater. Saved settings for the removed modules are ignored. The hardware sensor library (LibreHardwareMonitorLib and its MPL-2.0 dependencies) is no longer shipped.
  - **Upgrading during an Awake session:** Quotalis no longer puts the lid-close action back. If a session was running when you updated, set "When I close the lid" in Windows' power settings yourself. A leftover "Quotalis Awake Restore" scheduled task does nothing anymore and removes itself.
  - The island's unreachable drop-zone mode (Home Cloud's Drop state, its phases and timers) is gone from the state machine, with its tests.

### Documentation

- **ARCHITECTURE, STATUS, PERFORMANCE and DEVELOPMENT describe 0.7.0:** the removed modules, `--system-report` and the drop zone are gone; ARCHITECTURE gains a Hermes and Nous wallet section, and Secrets now says how the Nous sign-in is stored (DPAPI, not Credential Manager).

- **README rewritten for what Quotalis is today:** the Hermes column and Nous wallet, the usage strip, gold totals, usage by hour and peak hours, the in-app updater, every sign-in and what goes online. The "Claude Code alerts" feature, removed earlier, is no longer described. [docs/MODULES.md](docs/MODULES.md) gains a Hermes section and the current graph readout. The README media (hero GIF and screenshots) are regenerated by `tools/make-readme-media.py`, which now includes the Hermes shots and scales the taller three-column view to fit.

### Fixed

- **Settings, About** no longer says the update check is Quotalis's only network request; it lists what goes online and only when you switch it on.

### Build

- **`tools/privacy-scan.ps1` scans every path it is given** (before, only the first: a release scan of the publish folder and the zip skipped the zip), and matches personal strings as whole words only, so a short name inside another word (Brotli's word list in a .NET DLL spells "afterwardscurrently") is no longer a finding.

## [0.6.0] - 2026-10-25

### Added

- **A third column for Hermes Agent (version 0.6.0), in yellow.** Turn on **Hermes** in Settings, Modules. The Usage panel widens to three columns: Claude, Codex and Hermes.
  - **The Nous wallet, draining instead of filling.** Where Claude and Codex show plan usage climbing, Hermes shows the credits left in your Nous Portal wallet: a yellow bar that is full after a top-up (or a plan renewal) and drains as Hermes spends. It turns amber below a threshold you choose (default $5) and red at $0, with a **Top up Nous wallet** button that opens the portal's top-up page. Hover the amount for plan credits, purchased credits and the renewal date.
  - **Sign in once in Settings.** Settings, Modules, "Hermes and the Nous wallet", **Sign in to Nous Portal** shows a code and opens Nous's own page; approve it there and the column fills. This is Nous's device sign-in, the one Hermes itself uses, and for now Claudex borrows Hermes's app name, so the page says "Connect Hermes". Sign out forgets it.
  - **Read every second while Hermes works, every 5 minutes when it is quiet, never while the PC is locked or asleep.** After 5 minutes without a balance change or Hermes activity the fast reads stop; the next sign of activity starts them again. Throttling and Nous's firewall challenges back off by themselves. Reading the balance is a free account read: it runs no model and spends no credits.
  - **Hermes's own numbers, once a minute.** Today's fresh tokens (input, cache write, output, cache read, reasoning), API calls, sessions, what Hermes spent today (actual when Nous reported it, otherwise marked "estimated by Hermes"), and the model Hermes used last, which can change at any time. They come from Hermes's records: a Hermes install on this PC (`%LOCALAPPDATA%\hermes\state.db`, read-only), or a server's export copied with Windows' OpenSSH and your own key (the export job is in `tools/hermes`). Numbers only: no message text, prompts, titles or chat ids are ever read.
  - **The heatmap counts Hermes's tokens; the gold totals do not count its money.** Hermes spends real credits, a different thing from the API list-price equivalent of Claude and Codex, so the week, month and lifetime totals stay Claude and Codex only. A hovered day shows Hermes's tokens on a yellow bar.
  - **The usage strip** shows the wallet and the model.
- **`tools/privacy-scan.ps1`** fails when personal data would leave this PC: this PC's user name and profile path, private keys and tokens, plus your own strings listed in `%USERPROFILE%\.claudex\privacy-scan-patterns.txt` (kept outside the repository). It scans every file Git would commit, or a publish folder or portable zip, and prints only the file and the pattern's name.

### Security

- **The Nous sign-in is encrypted for your Windows account** (DPAPI) in `%USERPROFILE%\.claudex\nous-signin.bin`. Nous grants its tokens permission to run models, so they are never logged or written anywhere else, and Claudex never calls a model with them. Nous's refresh tokens work once: the new one is saved before it is used.

## [0.5.14] - 2026-10-22

### Added

- **Claude plan usage from claude.ai, with a one-time sign-in.** Settings, Modules, "Claude plan usage", **Sign in to claude.ai** opens claude.ai's own sign-in page in a small window, which closes itself once you're signed in. Claudex then reads your 5-hour and weekly usage the way claude.ai's own Usage page does: a few seconds after Claude Code writes a reply (at most every 15 seconds while it keeps writing), every 2 minutes otherwise, and less often while claude.ai can't be reached. It works in Claude desktop, terminal and IDE sessions alike.
  - **Never counts against your limits:** reading usage sends no messages to Claude, so it costs nothing.
  - **Private:** the label says so in Settings. Your sign-in (claude.ai's cookies) stays in a browser profile on this PC, `%USERPROFILE%\.claudex\claude-signin`. Claudex never sees your password, never reads the cookie values, never logs claude.ai's answers, and keeps only the two percentages and their reset times. **Sign out** clears the profile. **Refresh now** reads at once.
  - **Honest states:** an expired sign-in says so and offers **Sign in again**; an answer in an unknown format shows no percentage rather than a wrong one. The island's "Sign in…" button opens the same card.

### Changed

- **The terminal status line is now its own, optional row** in the same card, with Connect and Disconnect. It still hands over usage after every reply in a Claude Code terminal session.

### Removed

- **The Claude Stop hook** (`--claudex-stop-hook`). It had Claude read its usage card at the end of a turn, which cost model calls and counted against your limits every time. The installer removes its entries from Claude Code's settings, whichever copy of Claudex they ran, and an entry left anywhere else now ends at once without doing anything. Manual calibration (`--claudex-calibrate`) and the Codex Stop hook are unchanged.

## [0.5.13] - 2026-10-19

Everything still animates on the compositor at the display's refresh rate, so slower stays smooth. Tab switches and small elements keep their speed. One constant, `Motion.IslandPace`, sets it.

## [0.5.10] - 2026-10-19

### Fixed

- **Claude's plan bar and 5H / Weekly switch were missing whenever Claudex was started normally.** Claude desktop is a packaged (MSIX) app, and Windows redirects new files its hooks create under AppData into Claude's private package folder (`%LOCALAPPDATA%\Packages\Claude_…\LocalCache\Local\Claudex`). Every calibration from the Stop hook landed there, so Claudex started from Explorer, the Start menu or autostart never saw a reading. Only a copy started from inside a Claude session did, which is why a restart sometimes "fixed" it. The same redirection hid `pricing.json` from a normal start, so `codex-auto-review` went unpriced and history was re-priced back and forth at each start.
  - Files that hooks and other programs write for Claudex now live in **`%USERPROFILE%\.claudex`**, which Windows does not redirect: `claude-plan.json`, `calibration-log.jsonl`, `stop-hook-last.json`, `codex-stop-hook-last.json` and `pricing.json`.
  - At startup, Claudex brings in the newest copy of each from the old folder and from any packaged app's private copy, and merges the calibration log line by line. It only reads the old copies and never deletes them.

## [0.5.7] - 2026-10-17

### Added

- **Usage by hour and Claude's peak hours.** Below the usage graph, while no day is inspected or pinned:
  - **Hour strip:** 24 bars show when you use Claude and Codex (estimated API equivalent by local hour, last 28 days), with Anthropic's peak hours shaded bright yellow. Hovering a bar shows that hour's fresh tokens and cost.
  - **Peak share:** one line gives the share of your usage that falls in peak hours.
  - **Limit drain:** another compares how fast Claude's 5-hour limit fills per $1 of usage in peak versus off-peak hours, measured from your own exact readings. It pairs consecutive readings in the same 5-hour window, at most two hours apart, against the Claude usage logged between them, and shows the result once each side has 5 intervals and $1 of usage; until then it counts the readings so far. Readings come from Claudex's calibration log and, when it is still on this PC, Tokenz's older log (read only).
- **Codex history from your ChatGPT profile.** `Claudex.exe --claudex-import-codex-profile <profile.json>` imports the "Token activity" of a ChatGPT profile (the JSON behind `chatgpt.com/u/<name>`), so the usage graph covers Codex days from before Claudex tracked them.
  - **Which days:** only days before the first Codex day Claudex measured itself. The profile counts UTC days, so later days would overlap measured evenings and count them twice.
  - **Estimates:** the profile gives one total per day, so each total is split by your measured Codex mix (input, output, cached input) and valued at your measured cost per million tokens.
  - **Labels:** the day readout says "estimated" and "Codex from your ChatGPT profile", and the gold totals note that they include imported days.
  - **Provenance:** imported days are recorded in a new `imported_days` table. A later local measurement of the same day replaces the import, and re-pricing never touches imported days.
- **Settings, General, Keep the island open.** When on, the open island stays open when you click elsewhere or switch windows, instead of rolling back into the pill. It opens as soon as you turn the option on and when Claudex starts. Esc and the keyboard shortcut still close it, and full-screen and auto-hide apps still move it aside.
- **Settings, General, Claude peak hours:** start and end hour, weekdays in US Eastern time. The default is 8 AM to 2 PM, as Anthropic announced in March 2026; it can't be confirmed for later dates, hence the setting.

### Changed

- **The hours block and the day readout show together.** Inspecting or pinning a day no longer swaps the hour strip out: the day's numbers appear in their own area below it (a short hint stands there otherwise), so the layout never jumps. The open island grows at the bottom to fit both (up to 920 DIP, from 780).

- **Flaky GitHub module test.** `Without_gh_the_module_explains_how_to_connect` sometimes saw `Loading` instead of `Unavailable`: the module's first refresh ran on a real timer, held the fetch lock, and the test's own refresh returned before the status changed. ## [0.5.1] - 2026-10-17

### Fixed

- **Claudex could freeze right after a reboot** (no island, a tray icon that did nothing). The first scan of the Claude logs turned every line, including huge tool outputs, into a string. That forced full garbage collections while WinUI was still building the island, and the two deadlocked: the collection waited on WinUI's reference tracker, and the UI thread waited on the collection. ## [0.5.0] - 2026-10-17

### Added

- **Claude desktop calibration moved from Tokenz into Claudex.** `Claudex.exe --claudex-calibrate --five-hour X --five-hour-reset T --weekly Y --weekly-reset T [--plan P] [--by NAME] [--source TEXT]` saves exact plan usage from the Claude desktop app's usage card into Claudex's own plan file and prints "applied by Claudex". Reset times take ISO 8601 or Unix seconds; `--` marks a missing window.
- **Stop hook** `Claudex.exe --claudex-stop-hook`, the same rule Tokenz used: in a Claude desktop session over 2 minutes old it asks Claude to read `get_usage`, run the calibration and end with `🟠 Usage: Claude 5h <x>% · wk <y>%`. It skips a turn when a reading arrived in the last 30 seconds. Readings go to `%LOCALAPPDATA%\Claudex\calibration-log.jsonl`, the last decision to `stop-hook-last.json`.
- **Codex Stop hook moved from Tokenz into Claudex.** `Claudex.exe --claudex-codex-stop-hook` (in `~/.codex/hooks.json`), in Codex sessions over 2 minutes old, reads that session's latest exact `codex` rate-limit snapshot from its rollout log and asks Codex to end its reply with `🔵 Usage: Codex 5h <x>% · wk <y>%`, numbers already filled in, so Codex runs nothing for it. A window that has reset, or a session without a snapshot yet, shows `--`. It skips a turn within 30 seconds of the last report, and tells Codex to pass Claude numbers you give it from claude.ai to `--claudex-calibrate`. Its last decision goes to `%LOCALAPPDATA%\Claudex\codex-stop-hook-last.json`.
- **Installer hooks.** `Claudex.exe --claudex-hooks connect` points the Claude Code status line and Stop hook, and the Codex Stop hook, at that copy of Claudex (moving them from wherever an earlier copy put them, adding missing ones, leaving your own status line alone). The installer runs it as a task, "Connect Claude Code and Codex usage", on by default. `--claudex-hooks disconnect` removes only the entries that run that copy, and the uninstaller runs it first, so Claude Code and Codex never call a missing program.
- The installer offers a **desktop shortcut** and shows the new icon in its wizard.
- Settings, Modules, "Connect" adds the Stop hook next to the status line (and adds only the hook when you already have your own status line). "Disconnect" removes both, and nothing else.

### Removed

- **Tokenz is no longer read.** The `tokenz_status.json` reader, the "Reading from Tokenz" Settings text and Tokenz's stale and waiting messages are gone. Plan bars come only from Claudex's status line and its Stop hook.

## [0.3.0] - 2026-10-15

### Added

- **Awake** module (a coffee cup): keeps the PC awake for 1, 4 or 8 hours, a custom length or Always, also with the lid closed, so coding agents keep working. During a session the lid-close action is "Do nothing"; it is journaled first and put back at the end, at the next start or by a one-time scheduled task if the app is gone. ## [0.2.0] - 2026-10-13

### Added

- **Home Cloud drop zone:** drop files or folders onto the island to copy them to your own server. It is off until you set a target folder. It works in every state, also while the island is a notch or hidden: dragging toward the top edge arms the zone. Progress, success and error feedback; uploads go through a `.part` file and a rename. File names and paths are never logged. Settings, Home Cloud sets the target and the side, and turns it all off.
- `--homecloud-upload=<path>` sends a file through the Home Cloud pipeline for testing.
- **Quit Developer Island** in Settings, General: ends the whole app (island, tray icon, background work) after a confirmation. Closing Settings or hiding the island keeps it running.

### Fixed

- The island no longer disappears while switching apps: the Alt+Tab switcher and Task View were taken for fullscreen apps and hid it on every switch.
- The island stays above other apps' always-on-top windows: it takes the top again whenever another app comes to the front, without taking focus.
- Alt+F4 on the open island closes it like Esc instead of removing it until the next start.
- The usage graph reacts to hover, click and tap again; pointer input went to the scroll area behind it.
- The favorite star sits in the same place on every tab, Usage (Claude Code) included, and is no longer pushed aside or cut off by long names. On Usage it stands for the enabled providers.
- Git and GitHub CLI calls still running when the app quits end with it.
- The island can be dragged onto a monitor with a different scale. It used to jump back to its old monitor, and the capsule slid away from the cursor; now the point you hold stays under it, and a DPI change cannot end the drag.

- The island remembers its monitor by hardware id, so it returns to the right display after docking or reconnecting, when Windows renumbers the displays.
- Fullscreen apps and auto-hide apps count only on the island's own monitor, also when its window reaches into the neighbouring one.

## [0.1.0] - 2026-10-01

First public version.

### Added

- **The island:** a native WinUI 3 capsule with compact, live activity and expanded states, spring morphs from its anchor, six anchors or a free position on any monitor, a global shortcut (Ctrl + Alt + Space), tray menu and Start with Windows.
- **Claude Code and Codex usage** from their local logs: fresh and processed tokens by category, sessions, a 26-week usage graph with day tooltips, and an estimated API equivalent at list prices.

- **Auto-hide in apps:** retracts into a small notch (or hides) while a listed app such as Chrome is in front, deterministic under fast app switching.
- **Camera and microphone indicators** in every state, as small dots in the notch.
- **Demo mode** (`--demo`) with invented data, offscreen snapshots (`--snapshot`) and a hardware report (`--system-report`).
- Per-user installer and portable zip for Windows x64.
